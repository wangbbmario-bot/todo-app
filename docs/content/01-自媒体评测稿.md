> **利益关系声明（必读）**：这个工具是我自己写的、自己部署的、自己每天在用的。

## 一、先说结论

如果你需要一个**「记待办 + 拆解思路」一步到位**的工具，并且不介意它是网页（数据在自己服务器上），
这个工具能给你一个很轻的闭环。

不适合谁：**多人协作团队**、**需要严格提醒/GTD 分类体系**的人、**重度 GTD 爱好者**。原因后面讲得很具体。

---

## 二、我为什么要造它

用过的待办工具不少，但都卡在同一个地方：**待办和思维导图是两张皮。**

- 滴答清单 / 微软 To Do：记条目很快，但"一件事拆成三步"只能塞在描述里，写完就没人再看
- Notion：什么都能写，但打开要 3 秒，等页面渲染完我才想起要记什么
- 幕布 / XMind：拆解很漂亮，但拆完的结论不会自动变成一条待办

我想要的流程是：**一件事 → 拆成子任务 → 拆的过程中记下想法（便利贴）→ 拆完直接能执行**。
于是在 2026 年 10 月，我用 Next.js 写了这个东西。

## 三、它长什么样（三栏）

```
┌──────────┬──────────────────┬──────────────────────────────┐
│  清单列表  │    任务列表        │        任务画板（思维导图）      │
│  ├ 工作   │  高优先级 1         │   ┌────────┐                 │
│  ├ 南瓜   │  中优先级 10        │   │ 父任务  │──┬── 子任务A       │
│  ├ 已完成 │  低优先级 1         │   └────────┘  └── 子任务B       │
│  └ 垃圾桶 │  ...              │   ┌────────┐                   │
│          │                  │   │ 便利贴  │ ← 可缩放/可删除      │
└──────────┴──────────────────┴──────────────────────────────┘
```

左边是清单，中间是待办，右边是**这个任务专属的思维导图画板**。
三栏是联动的：中间点一条任务，右边立刻展开它的子任务和便利贴。

## 四、真实体验（我按顺序讲一遍）

### 1. 记一条待办：真的快

在中间的输入框打字，**回车就建好**，实测从按下回车到这行出现在列表里是 **47 毫秒**。
不用切页面、不用等弹窗。

任务按优先级自动分成三组（高/中/低），每条任务左边有一根彩色竖条表示优先级。
改优先级和设截止日期都在**右键菜单**里：右键 → 优先级 / 设置截止日期（今天、明天、下周一、清除）。
鼠标停在任务行上，右侧会浮出日历和垃圾桶两个小图标。

<!--CUT-->

### 2. 思维导图画板：这是我觉得最值的部分

点开任务，右侧画板自动展开：父任务在中间，子任务用**直角折线**连到右边。

- 拖动画布、滚轮缩放，左下角还有 +/- 按钮
- 右下角有个 **MiniMap 缩略图**，节点多的时候能一眼看清全局位置
- 画板里可以贴**便利贴**（文字或图片），便利贴能拖、能缩放、能删

便利贴的缩放是**实时**的——我拖动右下角那个小方块，本体和右下角缩略图会同步变大，
松手之前就已经是最终尺寸了。（这个我前后修了三轮才做对，中间还踩了个"预览窗动、本体不动"的坑。）

<!--CUT-->

### 3. 便利贴：随手记想法的地方

点一下便利贴就能直接在里面写字，**Enter 换行，Cmd/Ctrl+Enter 保存，Esc 退出编辑**。
选中便利贴后，它上方会出现一个「删除」按钮。

> 顺便说个我自己用出来的小知识：便利贴在编辑态按 Backspace 只会删文字，不会删掉便利贴本身——
> 要删得先按 Esc 退出编辑，再按 Backspace，或者直接点那个删除按钮。

### 4. 子任务和画板是双向的

画板上加的子任务，中间栏同步出现；中间栏加的子任务，画板上同步长出来。
这个"同一份数据两个视图"的设计，让我拆解的时候不用来回切页面。

### 5. 回收站

删掉的任务进垃圾桶（不是真删），可以恢复、可以永久删除、可以一键清空。
清单被删掉时，它下面的任务会一起进垃圾桶。

## 五、一些实测数字（我自己服务器上跑的）

| 指标 | 实测值 |
|---|---|
| 服务器配置 | 2 核 / 1.87GB 内存 / 79GB 硬盘（用了 33GB） |
| 前端资源体积 | JS 1.15MB（14 个 chunk），首屏 17 个请求 |
| 登录页可交互 | 371ms |
| 游客登录 → 清单列表渲染 | 1037ms |
| 切换清单 | 54ms |
| 回车新建任务 → 列表出现 | 47ms |
| 点任务 → 画板节点渲染 | 73ms |
| 刷新 → 清单渲染 | 153ms |
| 拖动便利贴缩放 | 30 步 778ms，视觉上跟手无延迟 |
| 数据库体积 | 8.9MB（目前 7 个用户 / 136 条任务 / 115 条子任务 / 74 张便利贴） |
| Web 镜像体积 | 263MB |

**为什么给你看这些数字**：自建工具最容易被质疑的就是"你自己吹当然快"。
数字是我用无头浏览器实测的，方法就是**用 DOM 出现的那一刻打点**，不是感觉。

## 六、它还有一个"多余"的功能：管理后台

一个人用的工具，我给它做了个后台（`/admin`）：

- 📊 仪表盘：总用户数 / 今日活跃 / 总任务数 / 完成率（目前 11%）/ 活跃清单
- 👥 用户管理：搜索、禁用、删除
- 📢 公告：发一条公告，所有人登录后顶部显示横幅
- 📜 审计日志：后台所有操作都留痕，不可删
- ⚙️ 系统配置：JSON KV 配置，每次改动都记审计

说实话，**这部分是我做过头了**。一个人用根本不需要。
但它后来救了我一次——有次数据出问题时，我第一反应是去审计日志翻"谁在什么时候改了什么"。

## 七、缺点（这一段是给"它到底好不好用"做判断用的）

**1. 没有全局搜索。**
这是我用得最痛的一个功能。任务一多，想找一条只能靠翻。
清单里的任务能按优先级看，但**不能按关键词搜**。想找"上周那个关于模型评测的任务"？只能一个个清单点过去。

**2. 没有提醒。**
截止日期就是个日期徽章，**到点了不会提醒你**，也没有微信/邮件/浏览器推送。
我现在的做法是：把有 deadline 的事单独放到一个清单里，每天早上开一次看一遍。有点笨，但管用。

**3. 多人协作基本没有。**
每个人一套清单各用各的，**没有共享清单、没有任务指派、没有评论**。
想跟同事同步进度，只能截图发微信。

**4. 移动端能用，但只算"能看能记"。**
手机上底部三个 tab（清单/任务/画板）切换很顺，但画板在手机上基本没法编辑——
**手指头拖不动那些小方块**。

**5. 最大的坑：多端同时开会互相覆盖。**
这是我实测出来才承认的：我用一个浏览器删掉了一个清单，**另一个还开着的旧标签页**
（它的数据是旧的）把这份旧数据又推回了服务器，那个清单就"复活"了。

原因说人话就是：客户端是**全量推送**，服务端是**最后写入者赢**，没有版本冲突处理。
所以现在的规矩是：**改完就刷新，别开两个标签页。**
我知道这不优雅，但一个人用的时候，遵守一条纪律比加一套冲突解决机制划算。

**6. 没有导出。**
数据在服务器上就是我的数据，但也意味着**我得自己保证它不丢**。
目前是定时 `pg_dump` + 保留 30 天，没有一键导出 CSV/Markdown 的按钮。
如果哪天这个服务器没了，我得写脚本从数据库里捞数据。

**7. 非管理员打开页面，控制台会有一条 403 报错。**
不影响使用，但看着不干净。（这条我留着当待办。）

**8. 界面是"功能型"，不精致。**
三栏布局信息密度高，但谈不上好看。配色素、动效少。
追求颜值的话，它不是你的菜。

## 八、适合谁 / 不适合谁

**适合：**
- 一个人用，数据想自己攥着（服务器在国内，登录即用）
- 工作里有"拆解"需求——比如写方案、做调研、理清一个复杂项目
- 喜欢"所见即所得"：拆解过程本身用便利贴画出来，而不是先想清楚再录进去
- 想在手机上快速记一条（打开网页 → 回车 → 完事）

**不适合：**
- 团队（没有协作）
- 靠提醒吃饭的人（没有推送）
- 待办超过几百条的人（没有搜索会要命）
- 想要开箱即用、不想折腾的人（数据在别人的服务器上，虽然可以自己部署）

## 十、最后

这一个月用下来，它替我解决的真问题只有一个：
**"拆解"和"执行"之间那道坎。**

别的待办工具让我更快地**记**东西，这个让我更愿意**想**东西——
因为想法可以直接摊在画板上，不用先在脑子里排版。

它当然不完美（没搜索、没提醒、没协作、多端会打架）。
但它是**为我一个人的用法定制的**，这一点，任何通用工具都给不了。
